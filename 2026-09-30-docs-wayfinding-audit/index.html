Docs wayfinding audit

Fifteen findings on how the docs site is organized and navigated: the sidebar, page structure, headings, search, code blocks and what the screenshots are for. Ranked by how many readers each one slows down. Visual styling is out of scope, and nothing here repeats the docs design audit (#1096–#1110).

Each before is a capture of the production build of main (2e4ec6f), light and dark follow your theme. Afters come from a prototype of the fixes on the same build; /mnt/project-files/docs-audit-hierarchy/prototype.patch has findings 1, 2, 5–10 and 12. Nothing has been filed.

1

HighNavigation

The sidebar serves four audiences in one list

The sidebar runs 42 entries for people using the app, people building apps for it, operators self-hosting it and contributors to the repo. At 900px tall the Self-hosting section starts below the fold on every guide, and Contributing sits under the operator docs. Screenshots (2,000 words) is the internal before/after workflow for design-review PRs, and Desktop app under Self-hosting ends with the release procedure. A user who opens the docs to learn the canvas scrolls past both.

Recommendation

Use Nextra's stock top-level tabs (type: "page" in the root _meta.ts): Guides, Self-hosting, Contributing. Each tab's sidebar lists only its own pages. Move development.mdx and screenshots.mdx into content/contributing/ and redirect /development and /screenshots. For the sidebar to scope cleanly the user guides also become a tab, so the change needs redirects for every moved route.

The after capture hides the other sections with a script, to show the end state. The patch adds the tabs; full scoping needs the Guides tab too.

2

HighPage structure

Agent chat is two pages, and the Coordinator has no entry

Agent chat is the longest page (2,600 words, 8,000px). Half of it is the Coordinator, under six H3s, so the TOC nests most of the page under one heading. The Coordinator is where the agent panel opens, yet the sidebar never names it. The page opens with two near-identical full-window screenshots (the hero, then the Coordinator), 400px apart. The Workspaces menu is described twice, once here under Choosing a target and again on Workspaces.

Recommendation

Split out The Coordinator as its own guide (its six H3s become H2s), and rename the rest Workspace chats. Drop the repeated hero from the top. Point links at /guides/coordinator (four pages link to #the-coordinator; the patch updates them). Keep Choosing a target short and link to the Workspaces menu instead of re-describing it.

3

HighScreenshots

Screenshot scale swings about 3× between neighbours

Full-window shots render the app at about 0.45× (UI text near 6px, and about 0.2× on a phone), so the hero on Intro, Quickstart and every guide is unreadable. Details render at up to 1.5× (frame.ts magnifies up to 1.6× and pads to a 560×360 minimum), so a two-item menu fills the column and its crop slices neighbours mid-word (“is canvas runs”, “d-web”). On Play mode, the player-controls detail shows a giant fragment of the page and the controls themselves sit below the fold.

Recommendation

Render details at life size: cap the magnification in framePage at 1× and show them at their CSS width, so a menu looks like a menu. Snap the crop to the focused element's box plus the pad, not to a fixed minimum that pulls in half-words. Keep full-window shots for the two pages where the whole layout is the point (Introduction, Core concepts); elsewhere crop to the region the section talks about.

The after capture only resizes the existing image; the crop fix needs a new capture.

4

MediumScreenshots

Screenshots repeat, and none says what to look at

The hero appears three times (Introduction, Quickstart step 4, Agent chat), each time with different alt text claiming it shows something else. The caption prop on <Screenshot> has no uses in the 34 pages, so a reader must work out from the alt text (which they can't see) what each image proves. Runs of two stacked shots with no text between them appear on Frames (twice), Home, Workspaces and Agent chat, and Play mode puts six shots in 400 words.

Recommendation

Give every screenshot one job: no repeats (Quickstart step 4 wants a result shot of the finished change; Agent chat wants none at the top). Add a short caption wherever two shots follow each other, and set a related pair side by side in a two-column grid that stacks on phones.

5

MediumNavigation

Guides are not in the order you meet the app

The 12 guides start with Home & organizing, although Quickstart drops you straight into a canvas and nobody organizes canvases until they have several. Reference pages (Settings, Keyboard shortcuts) sit in the same run as task guides, and Agent chat sits after Documents although you chat before you write documents.

Recommendation

Order by first use: The canvas, Repositories, Workspaces, Frames, Documents, The Coordinator, Workspace chats, Terminal tabs, Play mode, Sharing, Home & organizing. Then a Reference separator with Settings and Keyboard shortcuts (a stock type: "separator" in guides/_meta.ts).

6

MediumWayfinding

Breadcrumbs name sections the sidebar doesn't

The breadcrumb takes the folder name: Guides, Building, Self Hosting (title case, no hyphen). The sidebar calls the same sections Using Screenplay, Building for Screenplay and Self-hosting. Guides is a link that lands on Home & organizing, the first child. The Introduction page's H1 is “Screenplay” while the sidebar says Introduction.

Recommendation

Give each folder the sidebar's label as its title in _meta.ts (one line each), so breadcrumb and sidebar agree. Title the Introduction H1 “Introduction” or rename the row to match.

7

MediumPage structure

Desktop and hosted markers come in 11 spellings, and break anchors

Pages mark build-specific features as *(desktop)*, _Hosted._, *Hosted only.*, _(hosted)_ and six more variants: in headings, table cells, list items and callouts. In a heading the marker becomes part of the anchor, so Agent chat links to /guides/settings#coding-agents-desktop, and the TOC shows “GitHub (desktop)” in italics.

Recommendation

One <Only desktop /> / <Only hosted /> component rendering the stock outline Badge, placed on the line under a heading (never inside it) and at the start of a table cell. Anchors become #github and #coding-agents.

8

MediumSearch

Every page's search result starts with “Copy page”

Pagefind indexes the Copy page split button, so the top result for a page reads “Copy page Workspaces. A workspace is…”. Tables index as run-on text (“ShortcutAction V. Select tool. F. Frame tool”). For “rename branch” the section that holds Rename branch… (a row in the workspace menu table) ranks below Titles and the Workspaces menu, because table rows have no heading of their own.

Recommendation

Add data-pagefind-ignore to the Copy page button (one attribute, in the patch). For reference tables whose rows are what people search for (workspace menu, env vars, shortcuts), give each row an anchor so Pagefind can return it as a sub-result (see finding 11). Search's look is already ticketed (#1096, #1097).

9

MediumPage structure

Quickstart's steps break in two places

In step 2 a blank line before <kbd>N</kbd> splits the sentence: “on the home screen (or” ends a paragraph and “N ) creates…” starts the next. Keep going is numbered as step 5, though it is a list of optional next things, not a step. Step 4's result screenshot is the same hero the Introduction opened with.

Recommendation

Join the paragraph. Close <Steps> after step 4 and make Next steps an H2. Replace step 4's screenshot with a capture of the finished change (see finding 4).

10

MediumPage structure

“The Workspaces menu” and “The workspace menu” are two sections

The Workspaces page has an H2 The Workspaces menu (the list in the agent panel) and, three sections later, an H2 The workspace menu (the … on one row). In the TOC they differ only by a capital and an s, and links to either read the same in running text.

Recommendation

Rename the second to Workspace actions, which is also what the … menu does. Nothing links to #the-workspace-menu yet, so the rename is free.

11

MediumReference

Environment variables can't be linked one by one

Eight tables hold 34 rows, but a variable has no anchor, so other pages link to a section (“see Environment variables”) and the reader hunts. The tables disagree on columns: Agent has no Required column, Build switches says Values, and Required uses six vocabularies (“Yes”, “Production”, “Optional”, “Local dev only”, “Yes (default Yjs host)”, blank).

Recommendation

Give each variable row an id matching the variable (lower case) with a # that appears on hover, like Nextra's heading anchors, and link to rows from other pages. Use the same three columns (Variable, Required, Description) in every table, with Required limited to Yes, Optional and one conditional form (“If …”).

The after capture adds the anchor with a script; the patch doesn't include it.

12

LowCode blocks

Code blocks don't say which file they belong in

None of the 41 code blocks has a filename. The env quick start is meant for apps/app/.env.local, which the reader learns from a sentence two paragraphs up; the Knobs example is a component file, but reads like a shell snippet's neighbour.

Recommendation

Use Nextra's stock filename="…" meta on blocks that are file contents (env files, config, components). Leave shell commands bare. The title bar should get the restyled code block's hairline, not Nextra's grey fill.

13

LowPage structure

Settings sections are in a different order from the app

The page's intro lists the app's order (General, Coding agents, GitHub, Repository presets, Account), then the page covers GitHub before Coding agents. A reader following the app down the page jumps.

Recommendation

Order the H2s as the app's section list does.

14

LowPage structure

Troubleshooting is scattered where nobody looks for it

“No coding agent detected” is a callout at the very end of Agent chat, under the naming section. Why a preview never loads sits in Dev server & ports and in a callout at the end of Frames. None is reachable from the page where the symptom shows up except by reading to the end.

Recommendation

Close each affected page with a Troubleshooting H2 (symptom as a bold lead-in, fix after it), so it shows in the TOC and search. Link Frames' preview states to it.

15

LowNavigation

On phones, long pages have no in-page navigation

Nextra hides “On this page” below its desktop breakpoint, so Workspace chats (8,000px on desktop, far more on a phone) is one long scroll with no way to jump to The composer or Plan mode.

Recommendation

Splitting the longest pages (finding 2) covers most of it. For the rest, add a collapsed “On this page” disclosure under the title on small screens, built from the same TOC data.

Method: read all 34 pages' source and outlines, captured targeted pages at 1440×900 and 390×844, and ran eight search queries against the Pagefind index of a production build.

Out of lane and left to the other audits: the search panel's styling, colour and type of the code blocks and tables, and copy tone.
