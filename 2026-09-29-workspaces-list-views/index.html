Design exploration · wireframes · #885 · 29 Sep 2026

Sorting and grouping the Workspaces list

The sidebar's Workspaces list gets view options: sort by manual order, recent activity or name, and group by state. Three questions, three wireframed answers each. Pick one per question and only that gets built.

Blue marks what changes from todayWireframes only. The build uses stock shadcn sidebar and menu parts.

What stays the same in every option

Manual order is the default

A list you never touch looks exactly like today. Drag to reorder works only in Manual order; in the other sorts rows don't pick up.

It's your view only

The choice is remembered per canvas on your device and never written to the room, so collaborators' lists don't move.

Done stays one collapsed section

The Done (N) section from #976 stays at the bottom in every view, and a Done Workspace never shows anywhere else.

Recent activity

A Workspace records when a chat turn last started on it, and sorts newest first. A Workspace that never ran a turn uses when it was created.

Question 1

Where the view control lives

Home has no sort menu (the table's column headers sort) but uses a radio dropdown for its owner filter. The same radio dropdown fits here; the question is what opens it.

A
Recommended

In the existing … menu

The Workspaces … menu, which today holds Open existing git branch, gets Sort by and Group by state above it.

  • No new icon in the header
  • Where Linear and Claude put list options
  • The current sort isn't visible until you open the menu
B

A sort icon beside … and +

A third 24px header action with a sort glyph opens the same menu. The icon turns accent-coloured when a non-default view is on.

  • Obvious where to look
  • Three icons crowd a short label
  • A lone indicator state to design
C

The label opens it

"Workspaces" becomes a menu trigger with a small caret. When a non-default view is on, the label says so in muted text, e.g. "Workspaces · Name".

  • The current view is always named
  • Labels elsewhere in the sidebar aren't clickable
Question 2

How grouped sections look

With Group by state on. The sections match 2.1 C from round 2; question 3 decides which sections there are.

A
Recommended

Collapsible, like Done (N)

Every section is the same caret row as today's Done (N). Active sections start open, Done starts closed, and what you collapse is remembered with the view.

  • One section style in the list, reuses #976's row
  • Empty sections are hidden
  • Section rows are as tall as Workspace rows
B

Small muted headings

Plain text headings with a count and no caret. Done keeps its collapsed row at the bottom.

  • Lightest, reads like a Claude project list
  • Two section styles in one list
  • Can't fold away a long Working section
C

Sections replace the Workspaces label

Each state gets its own mono section label, like Workspaces and Canvas do today. The + and … move to the first label.

  • Uses the sidebar's own label style
  • Loses the Workspaces heading and its actions' home
  • Competes with the Canvas section below
Question 3

Which sections there are

You asked for Working, Needs you and Done. The row's state icon has six states; the question is how they fold into sections.

⠿Agent working (the 9-dot spinner) ◌Setting up (the regular spinner) ▲Setup failed ○Ready ◌̶Stopped (dashed circle) ✓Done
A
Recommended

Working, Needs you, Idle, Done

Needs you holds a failed setup or an open PR (waiting on your review or merge). Idle is the rest: ready or stopped with no open PR.

  • Your three words, plus somewhere for the quiet ones
  • Needs you is only things you can act on
  • Uses the PR badge too, not just the icon
B

One section per icon state

Working (with Setting up), Failed, Ready, Stopped, Done. The section is exactly what the row icon says.

  • No new rule to learn
  • Up to five sections for a handful of rows
  • No "Needs you"
C

Working and Needs you, then Done

Only two live sections: an agent is on it, or it's waiting on you (anything not working, including ready and stopped).

  • Fewest sections
  • A stopped Workspace you parked reads as needing you
