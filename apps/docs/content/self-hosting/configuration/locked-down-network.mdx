# Locked-down network

Some company machines reach the internet only through an outbound proxy, and
that proxy (or an internal host) signs its traffic with the company’s own
certificate authority. Screenplay runs there once three things are in place:
the proxy and CA in the server’s environment, a terminal module built for the
machine, and a Chromium for thumbnails.

## The build downloads only packages

The app ships its own fonts, so a production build fetches nothing. Once
`pnpm install` has finished, `next build` works with the network off.

`pnpm install` needs the package registry, and two packages fetch more while
they install: the terminal module and Puppeteer’s Chromium. Both are below.

## Proxy and certificate authority

Set these in the environment the server starts with:

```bash
export HTTPS_PROXY=http://proxy.corp:3128 https_proxy=http://proxy.corp:3128
export HTTP_PROXY=http://proxy.corp:3128 http_proxy=http://proxy.corp:3128
export NO_PROXY=localhost,127.0.0.1,::1,.localhost no_proxy=localhost,127.0.0.1,::1,.localhost
export NODE_USE_ENV_PROXY=1
export NODE_EXTRA_CA_CERTS=/etc/ssl/corp-ca.pem
```

They work like this:

- **Server requests** (GitHub, model providers) go through the proxy and trust
  the CA. `NODE_USE_ENV_PROXY=1` is what makes Node’s own requests read the
  proxy variables, and it needs Node 22.21 or later.
- **Everything the server starts** inherits them: coding CLIs, git in each chat,
  and each preview’s install and the preview itself.
- **Thumbnails**: Chromium goes through the same proxy. Chromium doesn’t read
  `NODE_EXTRA_CA_CERTS`, so while it’s set, a preview’s files from other hosts
  (a font or an image from a CDN) are fetched by the server instead, which
  trusts the CA. The preview page itself loads directly from this machine.
- **Loopback** never goes through the proxy. Keep `localhost`, `127.0.0.1`,
  `::1` and `.localhost` in `NO_PROXY`, and add internal hosts the proxy can’t
  reach.

Set both spellings of each proxy variable: curl and git read the lowercase one
first, Node the uppercase one. Every variable is in
[Environment variables](/self-hosting/environment-variables#outbound-network).

## The terminal module

The terminal runs on `node-pty`, a native module. There’s no prebuilt copy for
Linux, so `pnpm install` compiles it with `node-gyp`, which needs:

- Python 3
- `make`
- a C++ compiler (`g++` or `clang++`)

On Debian or Ubuntu, `sudo apt-get install python3 make g++` covers all three.

`node-gyp` also downloads Node’s headers from nodejs.org the first time. Give
it the proxy and CA with `npm_config_proxy=http://proxy.corp:3128` and
`npm_config_cafile=/etc/ssl/corp-ca.pem` while `pnpm install` runs. If
nodejs.org is blocked, point it at headers already on the machine instead, for
example `npm_config_nodedir=/usr/local` when Node was installed there with its
`include/node` folder.

## Chromium for thumbnails

Puppeteer downloads its Chromium during `pnpm install`, through `HTTPS_PROXY`
and trusting `NODE_EXTRA_CA_CERTS`. If that download is blocked:

- **A mirror:** set `PUPPETEER_CHROME_DOWNLOAD_BASE_URL` to a company mirror of
  Chrome for Testing.
- **A Chrome already on the machine:** set `PUPPETEER_SKIP_DOWNLOAD=1` before
  `pnpm install`, and
  [`CHROMIUM_PATH`](/self-hosting/environment-variables#serving) to that
  browser when the server starts.
