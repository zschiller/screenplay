# Headless

<Only headless />

**Headless** runs Screenplay from a clone of the repository on a machine you
control, usually a remote Linux dev box. One command checks the machine, builds
the app in production mode and serves it. You reach it from your own computer
over an SSH tunnel, as the **host**: the only person who writes.

It uses the same local backends as the desktop app: embedded Postgres
(PGlite), the local Yjs host, files on disk, a git worktree for each chat, and
the coding CLIs and `gh` installed on the machine. Thumbnails are taken with
headless Chrome.

## Run it

<Steps>

### Install the prerequisites

- Node 22 or later, and pnpm
- git
- Python 3, `make` and `g++`, to build the terminal module
  ([details](/self-hosting/configuration/locked-down-network#the-terminal-module))
- Chrome for thumbnails: Puppeteer downloads one during `pnpm install`, or set
  [`CHROMIUM_PATH`](/self-hosting/environment-variables#serving)
- at least one coding CLI, signed in: Claude Code, Codex or OpenCode, or the
  ones your config lists
- the GitHub CLI, `gh`, signed in, or the command your config names

### Clone and install

```bash
git clone https://github.com/zschiller/screenplay.git
cd screenplay
pnpm install
```

### Write a config file

Optional. Without one, every setting keeps its default and the data folder is
`~/.screenplay/headless`. With one, keep it in your data folder and name it
with `SCREENPLAY_CONFIG`:

```bash
export SCREENPLAY_CONFIG=/srv/screenplay/screenplay.config.jsonc
```

Every field is [below](#the-config-file).

### Start it

```bash
pnpm headless
```

It names each missing prerequisite and stops, so you can fix the machine
before anything is built. Then it builds, starts, and prints how to reach it:

```
  Screenplay is running (Headless).

  Host:    http://localhost:4100
  Frames:  http://*.localhost:1355 (portless)

  From your own computer, open a tunnel to both ports, then the host URL:

    ssh -N -L 4100:127.0.0.1:4100 -L 1355:127.0.0.1:1355 you@devbox
```

### Open the tunnel

Run the printed `ssh` line on your own computer, then open
`http://localhost:4100`.

</Steps>

`pnpm headless --no-build` serves the last build without building again.

## Listeners and the tunnel

The **host listener** listens on `127.0.0.1` only, so nobody else on the
network can reach it: whoever has a tunnel to it is the host. It serves the app
and its live connections (the canvas sync and the terminals) on one port.

Your own frames load through [portless](https://portless.sh), which the local
backend already runs each preview under. Each chat’s preview is registered with
portless and loads at `http://screenplay-<port>.localhost:1355`, so the tunnel
needs just two ports, the host listener and portless’s `1355`, however many
chats are running. Browsers send every `*.localhost` name to your own computer,
which is where the tunnel picks it up.

This holds even when the config picks another
[preview exposure](/self-hosting/configuration/preview-exposure), like a
company proxy’s `url-template`: that exposure and its sign-in are for viewers,
who reach the machine over the network. The host never needs the proxy or its
sign-in.

## Restarts

Nothing keeps the server running. When the machine stops (an idle stop, a
reboot), run `pnpm headless` again: canvases, chats, files and previews come
back from the data folder, and previews restart when their canvas opens.

The data folder holds:

| Folder or file | What |
| --- | --- |
| `pglite/` | The database |
| `yjs/` | Each canvas’s live document |
| `blobs/`, `files/` | Thumbnails, and files on canvases |
| `worktrees/` | Each chat’s code |
| `coordinator/` | Each canvas’s Coordinator folder |
| `extensions/` | A folder for each [extension](/self-hosting/configuration/extensions) that keeps files |
| `secrets.json` | Keys minted on first start; keep it with the rest |

## The config file

JSON with comments. Relative paths are relative to the file’s folder. A field
the file leaves out keeps its default. The server checks every field when it
starts and won’t start with a bad one; the message names each field.

```jsonc filename="screenplay.config.jsonc"
{
  // Where Screenplay keeps its data. Default: the folder this file is in.
  "dataFolder": ".",

  "listeners": {
    "host": { "port": 4100 },
  },

  // The company proxy that gives every port its own URL, for viewers.
  "previewExposure": {
    "use": "url-template",
    "origin": "https://{port}-box.corp.example",
    "signInUrl": "https://{port}-box.corp.example/",
    "ports": { "from": 20000, "to": 20199 },
  },

  "githubAccess": {
    "use": "gh-cli",
    "command": "corp-gh",
    "hostname": "ghe.corp.example",
  },

  "codingCli": [
    { "use": "claude-code" },
    { "use": "opencode", "key": "corp-code", "label": "Corp Code", "command": "corp-code" },
  ],

  "outboundProxy": {
    "url": "http://proxy.corp:3128",
    "noProxy": [".corp.example"],
    "caFile": "corp-ca.pem",
  },
}
```

### Settings

| Field | Default | |
| --- | --- | --- |
| `dataFolder` | the config file’s folder | Where Screenplay keeps its data |
| `listeners.host.port` | `4100` | The host listener’s port. It always listens on `127.0.0.1` |
| `listeners.viewers` | none | Network listeners for viewers: a list of `{ "name", "address", "port" }`. Printed at start; served once Sharing ships |
| `outboundProxy.url` | none | The proxy server requests go through, like `http://proxy.corp:3128` |
| `outboundProxy.noProxy` | loopback only | Hosts that skip the proxy. Loopback always does |
| `outboundProxy.caFile` | none | A PEM file of the certificate authorities the proxy uses |

`pnpm headless` sets the [outbound network](/self-hosting/configuration/locked-down-network)
variables from `outboundProxy` before the server starts.

### Interfaces

Each is `{ "use": "<id>", …options }`: a built-in’s bare id, or an
[extension’s](/self-hosting/configuration/extensions) `<extension>/<name>`.

| Field | Default | Built-ins |
| --- | --- | --- |
| `previewExposure` | `{ "use": "loopback" }` | `loopback`, `url-template`, `command`: [Preview exposure](/self-hosting/configuration/preview-exposure) |
| `githubAccess` | `{ "use": "gh-cli" }` | `gh-cli`, `oauth-account`: [GitHub access](/self-hosting/configuration/github-access) |
| `codingCli` | every built-in the machine has | A **list**: `claude-code`, `codex`, `opencode`: [Coding CLIs](#coding-clis) |

### Coding CLIs

`codingCli` lists the CLIs chats can use, in the order the model menu shows
them. With it, the setup check needs every command listed; without it, any one
built-in is enough.

| Built-in | Options |
| --- | --- |
| `claude-code` | none |
| `codex` | none |
| `opencode` | `key`, `label` and `command`, for an internal fork under another name; `listModels: false` when the fork can’t list its models |

## Environment

`pnpm headless` sets everything the server needs. You can also set:

| Variable | |
| --- | --- |
| `SCREENPLAY_CONFIG` | The config file |
| `CHROMIUM_PATH` | The Chrome thumbnails use, instead of Puppeteer’s |
| `PORTLESS_STATE_DIR` | Where portless keeps its routes. Default: `~/.portless` |
