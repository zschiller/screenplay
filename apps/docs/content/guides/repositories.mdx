# Repositories

A canvas runs code from one or more repositories. Each has the scripts that
set it up and start its dev server. You manage them in **Canvas settings**:
click **…** next to the canvas name at the top left and choose **Settings**.

<Screenshot
  name="canvas-settings"
  alt="Canvas settings open on Repositories, listing northwind-web with its scripts, Edit and a switch"
/>

The list holds every one of [your repositories](#your-repositories), each
with a switch for whether this canvas uses it, plus any other repository
already on the canvas. Each row shows the repository's short name (its label,
or the repository's own name) over its setup and run scripts. Turn a switch
on and the repository is on the canvas: chats can use it and new workspaces
start from its settings. On a shared canvas these settings are shared with
everyone on it, so a collaborator's new workspaces start the same way as
yours.

The Chats menu lists chats, not repositories: when a canvas has two
or more repositories, each [workspace](/guides/workspaces)'s row ends with its
repository's short name.

## Adding a repository

To set up a repository that isn't in your list yet, click **New repository**
at the end of the list in Canvas settings. It saves the repository to
[your repositories](#your-repositories) and turns it on for this canvas in one
step. On a canvas with no repository yet, **Add repository** on the empty
canvas and in the **Get started** checklist goes straight to the same choice,
without opening Canvas settings, and closes once the repository is added.
Adding a repository only adds it: no workspace starts until you ask for a
change.

<Screenshot name="add-project-menu" alt="The New repository menu" />

- **Open folder** _(desktop)_ picks a folder on your machine, usually your
  existing clone. Screenplay creates a separate worktree for each workspace
  and never touches your own checkout.
- **Open GitHub repository** opens a searchable picker of your GitHub
  repositories. On desktop you can also paste any clone URL, including
  non-GitHub hosts, and pick **Add _url_**.

**Configure repository** then opens with settings already detected from the
repository (**Detecting settings…**). Check them and click **Add repository**.
Picking a repository you already have, with the same name, updates that one
rather than adding a second; to use one you already have, turn its switch on
instead.

<Screenshot
  name="configure-project"
  alt="The Configure repository dialog with detected setup and run scripts"
/>

<Callout type="info">
  GitHub browsing needs a GitHub connection. On desktop, without one you can
  still add a local folder or paste a clone URL; git uses your machine's own
  credentials.
</Callout>

## Repository settings

| Setting                   | What it does                                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Label**                 | A short name, like `web` or `api`, shown instead of the repository's name.                                                     |
| **Setup script**          | Runs once when a workspace is created, e.g. `npm install`.                                                                     |
| **Run script**            | Starts the dev server that frames preview, e.g. `npm run dev`. Defaults to `npm run dev` when empty.                           |
| **Dev server port**       | _Hosted._ The port your dev server listens on.                                                                                 |
| **Environment variables** | _Hosted._ `KEY=value` lines injected into every workspace. Stored encrypted.                                                   |
| **Files to copy**         | _Desktop._ Glob patterns (default `.env*`) copied from your checkout into each new worktree, so local secrets come along.      |
| **Default frame size**    | The device size new frames open at. _(Advanced)_                                                                               |
| **System prompt**         | Extra instructions appended to the agent's prompt, e.g. "This repository's app is the Next.js app in `apps/web`". _(Advanced)_ |
| **Name**                  | Tells apart several of your repositories from the same GitHub repository, e.g. `web` and `api`. _(Advanced)_                   |

The run script has to serve on the port Screenplay assigns. Most frameworks
handle this automatically; see [Dev server & ports](/building/dev-server) if
yours doesn't.

To change settings later, click **Edit** on the repository in Canvas
settings. Changes apply to workspaces you create afterwards.

<Screenshot name="project-settings" alt="The Repository settings dialog" />

### Customizing a repository for one canvas

**Edit** in Canvas settings changes the repository on this canvas only. Once
its label or any setting differs from [your repository](#your-repositories)
in Settings, a small orange dot follows its name, with the tooltip
**Customized for this canvas**. Environment variable values don't count.

To undo it, click **Edit** and then **Reset to Settings**: the repository
takes your Settings again and the dot goes away.

To make an edit everywhere instead, tick **Also update Settings and my other
canvases** before you click **Save**. It's off by default. The edit goes to
your repository in Settings and to every canvas that uses it, including ones
where it was customized, so none of them has the dot afterwards. A canvas
keeps its own environment variable values if you changed them there. The box
only appears for your own repositories, since a repository someone else turned
on belongs to their Settings.

## Turning a repository off

In Canvas settings, turn off a repository's switch. Without workspaces it
comes off this canvas straight away. When workspaces use it, a confirm says
how many and lists each one, since they come off the canvas with it, and
warns if uncommitted work would be lost. When you're connected to GitHub, it
also offers **Also delete these _N_ branches on GitHub**, which is off by
default. The repository stays in Settings, so you can turn it back on later.

## Your repositories

**Settings → Repositories** lists your repositories and how each one runs.
Every repository you add from a canvas lands here. To set one up before any
canvas needs it, click **New repository** in Settings: it opens the same
picker and **Configure repository** form, and only saves the repository.
Editing a repository in Settings updates every canvas that uses it, except the
ones where it's [customized](#customizing-a-repository-for-one-canvas). A
canvas keeps its own environment variable values if you changed them there.

<Screenshot
  name="settings-presets"
  alt="Settings → Repositories: northwind-web with a 'web' repository"
/>

On desktop, every repository on your canvases also has a home in Settings:
the first time you open Settings after updating, any canvas repository that
matches none of yours is added to the list.

Deleting a repository in Settings doesn't take it off your canvases. The
confirm says how many canvases use it; each keeps its copy, which keeps
running its workspaces but stops getting your edits from Settings. It no
longer shows a dot, and you can still edit it on its canvas.

Your repositories are private to you and stored encrypted. Name them (`web`,
`api`, `docs`) to keep several from one GitHub repository. This is handy in
monorepos, where each app gets its own run script.

## Monorepos

A repository on a canvas previews **one** app. To work on two apps from the
same monorepo, add it as two of your repositories with different names. For example,
a `web` one running `pnpm --filter web dev` and a `docs` one running
`pnpm --filter docs dev`. Use the **System prompt** field to tell the agent
which folder is its app's root.
