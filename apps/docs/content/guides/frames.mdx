# Frames

A frame is a live preview of a workspace's dev server. It's a real browser
view, so hot reload, client-side routing, and app state all work as normal.

<Screenshot
  name="frame-selected"
  alt="A selected frame with its resize handles and floating toolbar"
/>

## Adding frames

- A new workspace gets a frame automatically once its dev server is up.
- The **Frame** tool (<kbd>F</kbd>) drops a 1280×800 frame where you click,
  or draws one where you drag. A new frame shows **No Workspace** until you
  pick a workspace for it from its title (**Choose a workspace**).
- **Show all routes** in the workspace menu adds a group with a frame for
  every route the workspace has visited.

## The title bar

Above each frame:

- **Name**: double-click to rename.
- **Workspace**, with its state icon, unless its
  [group](/guides/canvas#a-groups-workspace) names it because every frame in
  the group shows the same one. Click it to switch the frame's workspace.

Under the selected frame, an address bar shows its workspace and route. Click
the workspace to point this frame at another one, keeping its route and
state; this is how you compare workspaces on the same screen. Picking one
that differs from the other frames in its group moves the workspace from the
group's title onto each frame's. Click the route to edit
it in place, like a browser's address bar: type any path and press **Enter**, or
pick a route the workspace has visited from the list under the bar. **Esc**
puts the route back. Routes you visit while interacting
are added to the list automatically.

The route and scroll position are shared: when anyone viewing the canvas
navigates a frame, everyone else's copy follows. Your copy changes page
through the app's own router (Next's router, or the history API for React
Router, Vite and similar apps), so anything you typed or opened in the frame
stays put. Only a page with no client-side router reloads onto the new route.

## The frame toolbar

When exactly one frame is selected, a toolbar like a browser's appears under
it. From left to right:

| Button                | What it does                                                                                                                                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Back**, **Forward** | Step through the routes this frame has shown.                                                                                                                                                                                                                       |
| **Address**           | The frame's Workspace and route. Click the route to type a new one. **Reload** reloads the preview, and is highlighted when hot reload has disconnected.                                                                                                            |
| **Record flow**       | Like Interact, but every time you navigate, a snapshot of the previous page is left behind in the group. Clicking through a signup therefore lays the whole flow out as a row of screens. The address turns red with a screen count while recording.                |
| **Interact**          | Lets the frame take your clicks and scrolls, so you can use the app. The canvas stops panning over it. Double-clicking a frame does the same. The button and the frame's outline turn pink, and <kbd>Esc</kbd> returns to the canvas, even from inside the preview. |
| **Knobs**             | Live controls your app declares. See [Knobs](#knobs).                                                                                                                                                                                                               |
| **More**              | **Device size**, **Fit to content**, **Duplicate**, a **Workspace** submenu with **Open prototype player** and **Open in browser**, and **Delete frame**.                                                                                                           |

## Sizes

**More → Device size** sets exact device dimensions:

<Screenshot
  name="device-size-menu"
  alt="The Device size menu grouped into Desktop, Tablet and Mobile"
/>

| Group   | Presets                                                                                                                                                 |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop | 4K (3840×2160), 1920×1080, MacBook Pro 16″ (1728×1117), MacBook Pro 14″ (1512×982), Laptop 1440×900, Laptop 1280×800                                    |
| Tablet  | iPad Pro 13″, iPad Pro 11″, iPad Air 13″, iPad Air 11″, iPad mini, Galaxy Tab S10 Ultra                                                                 |
| Mobile  | iPhone 17 Pro Max, iPhone 17 Pro, iPhone 17, iPhone Air, iPhone SE, Pixel 9 Pro XL, Pixel 9 Pro, Galaxy S25 Ultra, Galaxy S25, Galaxy Z Fold (unfolded) |

You can also drag a corner handle. While resizing, the frame **snaps** to
nearby device sizes, which are outlined as you get close. Hold <kbd>⌘</kbd>
to resize freely. **Fit to content** resizes the frame to the page's full
document size, which is handy for capturing a whole long page.

A repository's **Default frame size** decides what new frames open at.

## Knobs

If your app declares [knobs](/building/knobs), the **Knobs** button opens live
controls: sliders, switches, text fields, selects, and color pickers. Changes
apply instantly and sync to everyone viewing the canvas. A dot on the button
means values differ from their defaults, and **Reset** in its header clears
them.

<Screenshot
  name="knobs-popover"

With no knobs declared, the popover explains what knobs are and offers **Ask
the agent to add a knob**, which opens the workspace's chat with a prompt
filled in.

## Shared state

When your app shares state through
[`@screenplay.space/state`](/building/shared-state), a small `{}` appears on
the route in the selected frame's address bar. Hover it to see the current JSON. The state is kept with the
frame and synced to everyone.

## Preview states

While there's no live page, a frame shows where its workspace is:

- **No Workspace** until you pick one for the frame.
- **Booting sandbox**, then **Starting dev server**, while the workspace boots.
- **Workspace failed to start** if setup failed, and **Dev server not
  responding** if the server doesn't answer in time. Both offer **Retry** and
  **Open logs**.
- **Workspace stopped** when its sandbox is stopped. Click **Start**.

<Callout type="info">
  A preview that never loads on desktop usually means the dev server isn't
  listening on the port Screenplay assigned. See [Dev server &
  ports](/building/dev-server).
</Callout>
