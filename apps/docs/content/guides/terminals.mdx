# Terminal tabs

A terminal tab is an interactive shell inside a workspace's sandbox, in the
same directory the agent works in. It opens in the terminal pane under the
workspace's chat, beside **Dev server** (see
[Terminals](/guides/agent#terminals)). Use one to run a CLI yourself, poke at
the repository, or drive a coding CLI in its own interactive interface.

<Screenshot name="terminal" alt="A terminal tab running Claude Code inside the customer-stories workspace" />

## Opening a terminal

Open the terminal pane (click a name under the composer, or press
<kbd>⌃</kbd> <kbd>`</kbd>) and click **+** after its tabs: it opens a terminal
with the coding CLI you used last, and the pane switches to it. If several
coding CLIs are available, the caret next to **+** lists them; pick one to
launch it straight away:

| CLI | Notes |
| --- | --- |
| **Claude Code** | Anthropic's coding CLI |
| **Codex** | OpenAI's coding CLI |
| **opencode (Vercel AI Gateway)** / **opencode (OpenAI‑compatible)** | opencode against the gateway or a compatible endpoint (terminal only) |

The CLI starts in the workspace. Quitting it (for example with
<kbd>Ctrl</kbd> <kbd>D</kbd>) drops you into a normal shell rather than closing
the tab.

Which CLIs are offered depends on how you run Screenplay:

- **Desktop**: any supported CLI installed on your machine, on its own login.
  Install and sign in from **Settings → Coding agents**.
- **Hosted**: the CLIs the operator enabled with `SANDBOX_HARNESSES`. The CLI
  never sees the real API key; the sandbox injects it on the way out. See
  [Coding CLIs](/self-hosting/configuration/byo-harnesses).

## Persistence

- Terminal tabs are **yours**. Collaborators on a shared canvas don't see
  them, and nothing typed there enters chat history.
- Tabs survive a **page reload** and reattach to the same running process.
- **Scrollback** isn't saved, and it ends with the sandbox.
- **Closing** a terminal tab ends its session for good. Closed terminals
  aren't archived the way chats are. If something is still running in it,
  such as a coding CLI or a dev server, Screenplay asks before closing; an
  idle shell closes at once. The pane then shows the tab next to it, or
  **Dev server**.

<Callout type="info">
  A terminal and a chat can run in the same workspace at the same time, and
  they share the same files. Commit from one and the other sees it.
</Callout>
