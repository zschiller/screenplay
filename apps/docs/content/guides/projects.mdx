# Projects

A project is a repository on a canvas, plus the scripts that set it up and
start its dev server. Projects appear under **Projects** in the canvas
sidebar, with their workspaces nested inside.

## Adding a project

Click the **Add project** icon next to **Projects**.

<Screenshot name="add-project-menu" alt="The Add project menu" />

- **Open project** *(desktop)* picks a folder on your machine, usually your
  existing clone. Screenplay creates a separate worktree for each workspace
  and never touches your own checkout.
- **Open GitHub project** opens a searchable picker. **Project presets**
  (repositories with a saved [preset](#project-presets)) are listed first,
  then **Other GitHub repositories**. On desktop you can also paste any clone
  URL, including non-GitHub hosts, and pick **Add *url***.

Picking a saved preset adds the project straight away. Otherwise
**Configure project** opens with settings already detected from the
repository (**Detecting settings…**). Check them and click **Add project**.

<Screenshot name="configure-project" alt="The Configure project dialog with detected setup and run scripts" />

<Callout type="info">
  GitHub browsing needs a GitHub connection. On desktop, without one you can
  still add a local folder or paste a clone URL; git uses your machine's own
  credentials.
</Callout>

## Project settings

| Setting | What it does |
| --- | --- |
| **Setup script** | Runs once when a workspace is created, e.g. `npm install`. |
| **Run script** | Starts the dev server that frames preview, e.g. `npm run dev`. Defaults to `npm run dev` when empty. |
| **Dev server port** | *Hosted.* The port your dev server listens on. |
| **Environment variables** | *Hosted.* `KEY=value` lines injected into every workspace. Stored encrypted. |
| **Files to copy** | *Desktop.* Glob patterns (default `.env*`) copied from your checkout into each new worktree, so local secrets come along. |
| **Default frame size** | The device size new frames open at. *(Advanced)* |
| **System prompt** | Extra instructions appended to the agent's prompt, e.g. "This project is the Next.js app in `apps/web`". *(Advanced)* |
| **Preset name** | Tells apart several presets for the same repository, e.g. `web` and `api`. *(Advanced)* |

The run script has to serve on the port Screenplay assigns. Most frameworks
handle this automatically; see [Dev server & ports](/building/dev-server) if
yours doesn't.

To change settings later, hover the project and choose **… → Settings**.
Changes apply to workspaces you create afterwards.

## The project menu

Hover a project and click **…**:

<Screenshot name="project-menu" alt="The project menu: Open existing git branch, Settings, Remove" />

- **Open existing git branch** opens a workspace on a branch that already exists
  instead of creating a new one.
- **Settings** edits the settings described above.
- **Remove** takes the project and all its workspaces off this canvas. The
  dialog lists each workspace and warns if uncommitted work would be lost.
  When you're connected to GitHub, it also offers **Also delete these *N*
  branches on GitHub**, which is off by default.

The **+** next to **…** creates a [new workspace](/guides/workspaces).

## Project presets

Check **Save these settings for next time** when adding a project, or manage
presets in **Settings → Project presets**. A preset is a reusable starting
point: once it has been copied into a canvas, editing the preset doesn't
change existing projects, and vice versa.

<Screenshot name="settings-presets" alt="Project presets in Settings: northwind-web with a 'web' preset" />

Presets are private to you and stored encrypted. Name them (`web`, `api`,
`docs`) to keep several per repository. This is handy in monorepos, where
each app becomes its own project with its own run script.

## Monorepos

A project previews **one** app. To work on two apps from the same monorepo,
add the repository twice with different presets. For example, a `web`
project running `pnpm --filter web dev` and a `docs` project running
`pnpm --filter docs dev`. Use the **System prompt** field to tell the agent
which folder is its project root.
