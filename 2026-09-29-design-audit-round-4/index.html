01

Toasts are set in the system font

Sonner sets its own font-family on the toaster, so every toast renders in the OS sans (SF on a Mac, DejaVu here) next to Instrument Sans. The Undo action keeps Sonner's 6px radius.

Fixfont-sans on the toaster and each toast; the action and cancel buttons take the 2px radius.

Where toasts sit is a separate question (see the first card below).

packages/ui/src/components/sonner.tsx

02

Section labels in pickers skip the mono label

Most pickers label their groups in the mono uppercase recipe (WORKSPACES, DOCUMENTS, DESKTOP). The @ mention list, / skills list, chat History, the keyboard shortcuts sheet and the Share dialog still use small sans in muted grey.

FixThe same classes the stock SelectLabel and SidebarGroupLabel use: font-mono text-2xs tracking-wider uppercase.

The comments panel's groups are frame names, not categories, so they stay as they are.

agent/mention-list.tsx · agent/skill-mention-list.tsx · agent/chat-history-menu.tsx · canvas/shortcut-sheet.tsx · share-room-dialog.tsx

03

Finished steps turn magenta

The step marker fills with --info, which became the magenta accent in #1007. A finished step in Set up Screenplay and in the Get started card now reads as selected or highlighted, while success is green everywhere else (Signed in, done Workspaces).

FixThe done marker uses bg-success. One component, both places.

local-setup/setup-step.tsx

04

Shortcut keys and the icon tile vanish on the empty canvas

In light mode --canvas-plane and --muted are the same grey, so the F and D key caps and the icon tile on the empty canvas have no fill. F and D read as stray letters.

FixA foreground tint for anything drawn straight on the plane. Dark mode was already fine and keeps its look.

canvas/canvas-empty-state.tsx

05

Text selection is the browser's blue

Selecting text in a Document (or any input) shows the default blue, the last blue left in the app after #1007. The canvas selection and focus rings are magenta.

Fix::selection takes a tint of the accent, a little stronger in dark mode so it stays visible.

app/globals.css

06

Home thumbnails sit on a grey that isn't the canvas

The thumbnail band is muted-foreground at 15% (#eaeaea light, #181818 dark), darker than the canvas it previews, and frames that were never captured (a Document, say) show as flat grey blocks.

FixThe band uses --canvas-plane, frames get the same hairline edge they have on the canvas, and an uncaptured frame is a blank page. The list view's row thumbnail follows.

The fixture world's capture timing differs between runs, so the Checkout flow tile shows two frames fewer in the after shot.

home/room-grid.tsx · home/room-table.tsx

07

The loading canvas shows old sidebar labels

While a canvas loads, its sidebar says Repositories and Canvas in sans. The loaded sidebar says WORKSPACES and CANVAS in mono, so the labels jump on load. The skeleton also has no zoom pill, so the top-right pill pops in.

FixWorkspaces and Canvas in the mono label style, and a zoom placeholder in the top-right pill.

canvas/canvas-skeleton.tsx

08

The stop button is an empty square

The Phosphor swap (#1008) left <SquareIcon fill="currentColor"> behind. Phosphor ignores fill, so Stop draws an outlined square on a faint button and looks like an unticked checkbox.

Fixweight="fill" on the icon, on the same solid button Send uses in that slot.

Every other confirm that loses work (Delete, Remove repository, Recreate) uses the tinted destructive button. The Coordinator's Remove card uses the solid black primary.

Fixvariant="destructive" for Remove; Open PR stays primary.

Two questions

These change something you'll notice across the app, so they're yours. They're also posted in the thread as cards.

Move toasts to the top center?

Sonner's default is bottom-right, which is where the chat composer and Send live whenever chat is open, and on Home the error toast covers the last canvas card. I read this from where both are placed; no captured screen shows a toast over the composer.

  • Top center (recommended)Clear of the composer, the tool pill and the Get started card.
  • Bottom centerWhere Figma puts them, but it sits on the canvas tool pill.
  • Keep bottom-rightNo change.

Name chats and Workspaces in sentence case?

The naming prompt asks the model for “title case” labels, and a Workspace's title is its first chat's label (#881). Real Workspaces come out as Hero Gradient & Trust Line while every other string in the app is sentence case. The fixture world is written in sentence case, so the screenshots mostly hide it.

  • Sentence case (recommended)Change the prompt, its examples and the no-model fallback; existing names stay.
  • Keep Title CaseNo change.

Left out on purpose

Things that looked off at first and turned out to be deliberate, stock, or bigger than a polish ticket.

  • Two presets named LaptopThe device list names presets by device and shows the size in its own column on purpose (round 3).
  • Logs panel spacingIt matches the terminal's metrics so switching tabs doesn't move the text.
  • Player controls fill black when onThey match the canvas tool pill, which uses the same FloatingToolbar.
  • Canvas settings layoutIt's the stock shadcn settings-dialog block, chevron breadcrumb included.
  • Dialogs opened from Canvas settings stack their overlaysStock Radix behaviour.
  • Long git branches wrap in the Workspace hover cardThey break at a hyphen, and the card is where the full value belongs.
  • Chat tab labels under the close buttonI tried left-aligning them and it made no visible difference, so I dropped it.
  • Document typographyBold sans headings in Documents are a bigger call than a polish ticket.
