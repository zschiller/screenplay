PR 1 · Bug · 1-line fix plus toasts · about 6 files

Make ⌘Z undo canvas edits, and delete one way

Deleting a frame or document is permanent for everyone today, and the shortcut sheet promises an Undo that does nothing. Both audits reproduced it. It goes first because the delete rule in this PR depends on undo working.

Depends on
None. Ship first.
Touches
lib/yjs/react.ts, canvas delete paths (toolbar, Delete key, sidebar rows), chat-history-menu.tsx, canvas-memory-section.tsx
P2 = I1

⌘Z and ⌘⇧Z work for every canvas edit

The room's UndoManager has no trackedOrigins, so every edit committed with CANVAS_OPS_ORIGIN skips the stack (still true on main, lib/yjs/react.ts:112). Track that origin. Moving, resizing, grouping and deleting all become undoable.

I1 + I5

One delete rule: if Undo can bring it back, don't ask

Frames, documents, groups and canvas memory entries delete at once from every path, with a stock toast offering Undo. Canvases, folders, Workspaces, repositories and presets keep ConfirmDialog. Chat deletion in History moves from press-twice to ConfirmDialog. The toolbar item is labelled Delete, like the sidebar. Dropping the sidebar's confirm is a call below.

PR 2 · Bug · keyboard handler · about 8 files

Keep canvas keys out of menus, dialogs and text

With a menu open, Backspace deletes the frame behind it and Escape both closes the menu and drops the selection. ⌘B in a document also collapses the sidebar, and Ctrl does nothing on Windows and Linux. All of it lives in one handler, so it ships as one pass.

Depends on
After PR 1, which changes what the Delete key path does.
Touches
use-canvas-keyboard.ts, use-canvas-gesture.ts, composer.tsx, frame-nav.tsx, lib/canvas/shortcuts.ts, player-chat-host.tsx, comments-panel.tsx
I2

One guard at the top of the canvas handler

Return on e.defaultPrevented, and for every key but Escape when the target is inside a menu, dialog or popover (reuse isTypingOrInOverlay from home). Space pans only when the target isn't interactive. Escape in the composer blurs it and stops. The frame-nav workaround goes.

I16 + D

⌘B, ⌘I and ⌘. behave in text, and accept Ctrl

⌘B and ⌘. skip while editing text; ⌘I closes the chat from the composer; the composer drops StarterKit bold and italic, since chat is sent as plain text. All three, and the drag modifiers the docs audit found (use-canvas-gesture.ts:205), accept metaKey || ctrlKey as undo already does.

I notes

Three shortcut loose ends

Esc closes the Comments panel from anywhere (the player's pattern). The player's Collapse chat hint says ⌘I but nothing handles it. The ? sheet gains ⌘E and ⌘↵.
