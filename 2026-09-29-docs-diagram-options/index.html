Replacing the ASCII diagrams

The docs have three ASCII diagrams. Below are three ways to redraw them, each shown on the two real diagrams (Core concepts and Self-hosting) in light and dark, in the docs' own type and colour. The third ASCII block, the screenshots folder listing, is a file tree; option C shows how it would look too.

Option A

Mermaid

Write ```mermaid fences in the MDX. Nextra 4 already ships Mermaid, so there's nothing to install; our CSS restyles its output. Mermaid lays the boxes out itself.

  • Anyone can edit a diagram as text, right in the page.
  • Already bundled with Nextra.
  • Automatic layout: you can't place things, so it looks generic and wide diagrams shrink.
  • Rendered in the browser with a large script; text inside isn't in search.
Option B

Hand-drawn SVG

Each diagram is an SVG drawn for its page, kept as a small component in apps/docs/components/diagrams/, with colours from our tokens so it follows the theme. Because every box is placed by hand, a diagram can show things ASCII can't, like the canvas containing its repositories and layers.

Core concepts

  • Best-looking and most expressive: nesting, grouping, exact alignment.
  • Static markup, no script, crisp at any zoom.
  • Editing means moving coordinates, so docs changes need a diagram change by hand.
  • Scales down as one picture on phones, so the text gets small.
Option C

HTML diagram components

Two small components styled with our tokens: <Tree> for hierarchies (concepts and the folder listing) and <SystemMap> for the one-to-many architecture. The MDX holds the content as plain data; the component draws the boxes and connectors.

The seeded world

  • Real text: selectable, searchable, and readable on a phone.
  • Editing is changing a line of MDX; the layout follows.
  • Only fits trees and hub-and-spoke shapes; a new shape needs a new component.
  • Less freedom than B (no containment picture for concepts).
Recommendation

C, HTML components

All three diagrams are trees or one hub with spokes, which is exactly what these components draw. The text stays real, so it reads on phones and shows up in search, and future docs edits don't need anyone to redraw a picture. B looks a little richer for Core concepts; if you like that containment picture, I'd use B for that one diagram and C for the rest.
