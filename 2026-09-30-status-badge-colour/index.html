Status Badge Colour

The outlined status badges put their colour only in the 12px icon: PR numbers on Workspace rows, group labels and the address bar, failed tool calls in a turn summary, plan Approved and Changes requested, Signed in, and the unpushed work warning. Four ways to carry more of the colour, each shown as a specimen and in real app screens (left light, right dark). Neutral badges like Queued and Not installed stay as they are in every option.

Recommendation: A2, coloured text a shade calmer than the icon. It keeps what made A right (badges agree with the chat header PR button and the red-text error banners, no new Badge variant) and fixes A's light-mode contrast without touching the status tokens.

Corner radius: every badge should use the app's 1.6px corner. The PR number badge uses 1.2px and is 16px tall and the failed-tool chip 18px where other badges are 20px, so the ticket would bring it in line. The earlier version of this page drew its specimens with 6px corners by mistake; they now match the app.

C. No outline

Coloured icon and text with no box at all.

Lightest option, like GitHub's inline state text. It loses the chip shape that separates a PR number or a failure from the sentence or title beside it, so “#470” starts to look like part of the name, and the failure chip slides up onto the summary line.
