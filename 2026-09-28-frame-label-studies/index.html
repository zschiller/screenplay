Frame label studies

You picked groups plus the address bar. A group owns a Workspace and names it once. A single frame switches from its address bar. A frame label mentions a Workspace only when that frame differs from its group. This round works through every state that direction has to handle.

1

At rest

Three groups and a single frame. Checkout is all on one Workspace, so only its group label mentions it. In Cart, one frame was switched on its own, so that frame's label carries its Workspace. Order confirmation is a group of one; groups of one have no group label today, so the frame label carries the Workspace. The route is gone from every unselected label, since the selected frame's address bar and the frame body both show it.

What got lighter

  • Eight frame labels, and only two mention a Workspace, both for a reason.
  • No stubs. Wherever the Workspace shows, it shows in full.
  • No route pills on labels or sidebar rows.

What stayed

  • The Workspace pill is the same element as in the Workspace list, so the colour link to the sidebar holds.
  • Names, group labels and their positions don't move.

What's new

  • A pill on the group label line.
  • The idea that a group has a Workspace.
2

How the group label shows its Workspace

Three weights for the same information. I'd use the pill: it's the element that already stands for a Workspace in the sidebar, so the two read as the same thing, and it needs no new style.

3

Switching a group

Hovering the group's pill shows the up-down chevron, the same affordance the route pill uses today. Pressing it opens the Workspace list you already have, with status and diff. Picking one moves every frame that follows the group; each keeps its route, state and size. Frames switched on their own stay put, and the menu says so before you pick.

What moves

Every frame that follows the group. Documents in the group are unaffected.

What doesn't

A frame switched on its own. The footer names it so the result isn't a surprise.

Everyone sees it

The group's Workspace lives in the canvas, like a frame's does today, so a switch shows for everyone on the canvas.

Undo

One switch is one undo step, however many frames it moved.

4

Switching one frame

The selected frame's address bar starts with its Workspace, like the site in a browser's address bar. Pressing it opens the same list. Picking something other than the group's Workspace makes that frame an exception, and its label gains the pill. For a frame that's already an exception, the first item returns it to the group.

Why the address bar

  • It's the one control that is always about one frame.
  • A browser keeps the path when you change the host, which is exactly what switching does.
  • It replaces today's hidden stub, so the feature gets easier to find, not harder.

The host segment

  • It uses the Workspace's text colour and a dot, not a filled pill, so the field still reads as one address.
  • A long branch name truncates from the end. The path always shows in full.

Without selecting

  • An exception's own pill on its label is also a switcher, so you can send it back without selecting it.
  • A frame that follows its group has nothing to press on its label; you select it and use the address bar.
5

Sidebar

The Canvas list mirrors the canvas. A group row ends with its Workspace pill. Frame rows are names, except exceptions, which end with theirs. Hovering a Workspace row lights up the groups and frames that use it, the cross-highlight you kept from #793, now at group level too.

6

Edge cases

Dragging a frame into a group

It takes the group's Workspace, keeping its route and state. If it was an exception, it stays one. Dragging a frame out on its own keeps the Workspace it had and shows it on its label, since a group of one has no group label.

Merging two groups

The merged group keeps the Workspace of the group you dropped onto. Frames from the other group that were on a different Workspace become exceptions, so nothing changes what it shows.

A group of documents only

No Workspace, no pill. The first frame added to it sets it.

New frames

A frame added to a group follows it. A frame created by a new Workspace (the seeded frames) starts a new group on that Workspace, as it does now.

7

What changes underneath

  1. Groups get a Workspace. IframeLayerGroupData gains an optional branchId. A frame's branchId becomes an exception: set only when it differs from its group.
  2. Existing canvases convert on load. A group whose frames all share one Workspace takes it, and their own values clear. A mixed group takes its leftmost frame's Workspace, and the rest become exceptions. Nothing changes on screen.
  3. Switching reuses today's code. Assigning a Workspace already keeps route and state per frame. A group switch runs it for each following frame in one transaction.
  4. Groups of one keep today's behaviour. The Workspace shows on the frame label because there is no group label to put it on.

If you want to build it, I'd split it into four tickets: the model and conversion, the group label and its switcher, the address bar host, and the sidebar rows.

Open questions

  1. Pill, dot and text, or muted text on the group label? I recommend the pill.
  2. Should a group switch also move exceptions? I recommend no, and naming them in the menu footer.
  3. Should the address bar show the Workspace for frames that follow their group? I recommend yes, so the switcher is always in the same place.
