Worth your oversight

  • PR 7 changes the release script and needs a release cut from your Mac before the homepage link flips. I'd run the release over Remote Control with you, not overnight.
  • Release notes. A user-facing summary above the generated PR list means someone writes one per release. I'd draft it from the merged PRs each time; tell me if you'd rather keep releases as they are.
  • PR 1's self-hosting copy names what you pay for (hosting and model usage) and the extra services. It's accurate, but it's a more candid pitch than today's “It's free”.
  • PR 4's Coordinator excerpt invents one example ask (“Try three versions of the pricing hero”). It uses the page's existing Northwind content, but check the wording in the preview.
  • PR 6's pin and facepile are new excerpt UI. They follow the app's comment components; if the app's comments change, this excerpt goes stale like the others.

Defaults I picked and what was merged

  • Pictures go first in each step (H10), so the N1 subgrid becomes excerpt, label, title, body.
  • Phones get two muted links (H7), not a menu sheet.
  • N14 is dropped from the nits branch because P13 removes the links it fixes.
  • Where both audits found the same thing (N5 and H9, N13 and H12, N9 and H14, N7 and H13) it ships once, in PR 2.
  • Checked against your rules: nothing proposes light styling, film wordplay, screenshots instead of HTML excerpts, or a new headline (H1 only moves the line break), and self-hosting keeps leading with multiplayer and comments.

PR 1 · Copy only · 6 files

Correct the claims that aren't true

Four claims fail a one-minute check by a developer. This is the only PR where waiting costs trust, and it touches no layout, so it can merge before anything else.

Depends on
None. Ship first.
Touches
features.tsx, faq.tsx, scenes.tsx (Step 3 copy), self-hosting.tsx, footer.tsx, app/layout.tsx (meta description)
P2

Drop “works offline” and “your code stays on your machine”

Card: “Runs on your Mac. No account and no Screenplay servers. Sandboxes are git worktrees on your disk and your canvases live in a local database. Your agent talks to its model provider, just as it does in your terminal.” FAQ becomes “Does my code leave my machine? Only through your agent.” Checked: chat goes through Claude Code or Codex, the adapter is fetched with npx, and repo detection sends the README to the model.

P3

Knobs change one frame, not every branch

“Ask the agent to expose spacing, color or copy as knobs, then drag a slider to try values in a frame without another prompt.” Knob values are stored per frame (use-layer-mutations.ts:146). The package name leaves the card.

P4

Cut “Invite your team to review” from the desktop steps

Step 3 ends at “Click through them and check phone sizes.” Sharing, cursors and comments are excluded from the desktop build; teams stay in Self-hosting.

P5

Fix the agent list

“Use Claude Code or Codex with the subscription you already have, and pick the model per chat.” The FAQ explains that opencode runs in terminal tabs only and the built-in agent is self-hosted only. The meta description loses opencode too (P14).

P7

Answer “What do I need?” first in the FAQ

New first item: a Mac with Apple Silicon, a Claude Code or Codex account, and a repository with a dev server; GitHub only for pull requests. “Do I need to change my app?” drops the wrong “synced state across frames” line and says the dev server just needs to use the port it's given.

P8

Say what self-hosting really needs

Lede: “Deploy the web app for your team and share a canvas. The software is free and MIT licensed; you pay for hosting and model usage.” FAQ lists Postgres, Liveblocks, Vercel Blob, Vercel Sandbox and the model keys. The section still leads with multiplayer and comments.

P13

Footer: docs links instead of the npm packages

Developers column: Docs, GitHub, Self-hosting guide, Knobs guide. This finishes what PR #1194 started and makes visual nit N14 (the mono package links' line height) unnecessary.

P9

Problem headline with the reader as the one who wants versions

“Three versions means three setups and three tabs.” Body unchanged. This one is a wording call, listed under Needs your call; the PR ships it unless you say otherwise.
