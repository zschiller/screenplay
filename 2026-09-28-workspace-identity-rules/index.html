One way to show a Workspace

A Workspace shows up in eleven places. Some draw it as a colour pill, one as a dot and coloured text, some as a plain title, and the status icon appears on some and not others. This page lists what ships today, proposes one rule for colour and one for status, and shows each option in light and dark.

Proposed rule

Sort every surface into one of two roles. The role decides what it shows.

The Workspace is the subjectPlain titleLists of Workspaces (sidebar, both switchers, the chat picker, dialogs) and headers that name the current one (chat header, hover card). You are looking at Workspaces, so the name is enough.
Something else points at itColour pillCanvas group labels, exception frame labels, their Canvas list rows, and the address bar host. Here the frame or group is the subject and the pill says which Workspace it runs on; colour is what lets you scan a busy canvas.
StatusWorkspace state, never PR stateThe icon is always the Workspace's own state from #963: setting up, agent working, ready, stopped, failed, and Done (question 3). PR state appears only as the PR number at the end of a list row. Where the icon appears is question 2.

Question 1: where colour appears

Decided 28 Sep: D, no colour anywhere

Each option shows the same five surfaces: sidebar rows, chat header with its picker open, a canvas group with an exception frame, the address bar, and the Canvas list. Status follows the recommended rule in all four so only colour changes.

Question 2: where the status icon appears

Decided: S3, everywhere

All three use colour option D, your pick, so only status changes. With no colour, the status icon is the only thing that sets a Workspace mention apart. In the sample the group runs on "Checkout polish" (agent working, PR #482 open) and the Payment frame is an exception on "Apple Pay button", which is Done (PR #479 merged).

Question 4: how PR state is drawn

Decided: P2, outline badge

One PR treatment everywhere: after the Workspace name in headers, canvas labels, the Canvas list and the address bar, and at the end of list rows (replacing the line count). It is the first thing to go when there isn't room: the name never truncates to make room for it, so in the mockups the narrow Payment frame label drops it while the wider group label keeps it. Draft and closed PRs follow the same shape in GitHub's grey and red.

Question 3: what makes a Workspace Done

Decided: marked from the menu only

Today there is no Done. A Workspace's status is only its sandbox state (creating, starting, running, error, stopped). #885 wants the list grouped by Working, Needs you and Done, and #890's task rows show done, but neither says what makes a Workspace done. Each option below uses the same state icon, a muted check circle, and sorts the row under Done when grouping ships.

Merged PR Done happens by itself when the Workspace's PR merges. No new control, but work that never gets a PR (a spike, a prototype) can't be Done.
Marked from the menu "Mark as done" in the Workspace … menu (and "Reopen" to undo). It stops the sandbox, keeps chats and frames. Nothing happens by itself.
Both (recommended) Merging marks it Done; the menu covers everything else. The merged purple icon stays at the row end, the check circle leads.
