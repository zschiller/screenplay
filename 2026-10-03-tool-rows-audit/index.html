Calls for you

Pick one option per call, add a note if you like, then copy your picks and paste them in the thread. The row font is decided (UI font), so it's no longer a call.

1. How should a diff's edited lines be coloured?

A is GitHub's diff: the tint and the + and − mark the change, and the code still reads as code. B shouts louder and loses the syntax colours on exactly the lines you want to read.

2. Do the colours and markdown in round 3 look right?

The log marks are a guess from words like "error" and "warn"; B drops the guessing and only shows colours a tool printed.

3. Should a row open when its result only repeats the label?

A chevron promises something new. Finished canvas changes already work this way.

4. How should a file path show?

A keeps two files with the same name apart and matches the hosted agent today.

5. How should a Frame Drive show in chat?

The person is watching the frame during a drive, so ten rows repeat what they just saw. B builds on A's labels.

6. Where should harness housekeeping hide (ToolSearch, Compact conversation, Ready to code?)

None of them says anything about the work; a failed one still shows.

7. How should a pressed key show?

A follows the Kbd rule; the caps are sized so the row keeps its height.
