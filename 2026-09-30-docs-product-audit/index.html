Docs Product Audit

Does apps/docs explain the product as it is today? I read all 39 pages and checked every concrete claim against the app code. The guides are mostly accurate, detailed and current with the last day of merges. The problems are at the top and the edges. The Coordinator, now the product's front door, is missing from the pages that introduce the product. Desktop users are promised Coordinator features that only the web app has. A few features are documented but don't exist, and a few real ones aren't documented. Findings are ranked by how much they would mislead a new user. Nothing from the visual docs audit (#1096–#1110) is repeated here, and no tickets are filed.

If you pick five
  1. Put the Coordinator into the Introduction and Core concepts, including the concepts diagram.
  2. Say plainly that the desktop Coordinator can't start workspaces, try variants, open PRs or remove workspaces, and what to do instead.
  3. Remove the document "select text, send to agent" sections (or wire the code up). They describe UI that isn't there.
  4. Split Agent chat into a Coordinator page and a Workspace chat page, which also fixes where memory lives.
  5. Fix play mode's link and knob-sync claims.

High impact

01

The Coordinator is missing from the Introduction and Core concepts

High
index.mdx · concepts.mdx · components/diagram/diagrams.tsx
Today

Since #1182 the first thing a new user does is ask the Coordinator. The Quickstart says so. The two pages that explain what Screenplay is don't mention it:

You drive the agent from a chat panel beside it and watch the previews update as it works. (index.mdx)
The agent does the coding. Every workspace has a chat panel where you give it instructions… (concepts.mdx, Agent)

The concepts diagram shows Canvas, Repository, Workspace, Frame and Document, with no agent at all. Canvas memory is explained only deep in the Agent chat guide. Groups get one sentence under Frame and read as frame-only, though they hold documents too. The "Names you'll see in the code" table lacks Coordinator → Room Target, Group → Iframe Layer Group and Agent → Engine.

Proposed fix
  • Introduction: rewrite the opening sentence around the real loop. For example: "Ask the Coordinator for a change. It hands the work to a workspace's agent, and you watch the app change in a live frame." Add a bullet: Ask in one place. The Coordinator sees the whole canvas and sends work to each workspace.
  • Core concepts: add a Coordinator section between Canvas and Repository (one chat per canvas, sees everything, never edits code, sends work to workspace agents). Add Memory as a short section. Rename "Agent" to "Workspace agent". Give Group its own short section.
  • Diagram: add the Coordinator on the canvas, with arrows to each workspace's agent.
  • Names table: add the three missing rows.

Recommendation: Do this first. Everything else in the guides already assumes the Coordinator, so the intro is the only place it's out of step.

02

Desktop users are promised Coordinator features that only the web app has

High
guides/agent.mdx · quickstart.mdx · building/skills.mdx
Today

On desktop, every chat runs through a coding CLI, and the Coordinator's plan-gated tools (create workspaces, open PR, remove workspace) refuse over MCP (app/api/agent/mcp/route.ts:139). The docs mention this once, at the end of a subsection:

When the Coordinator runs on a desktop harness (Claude Code or Codex), it can't show you a plan or a confirm card yet, so it can't start workspaces, open pull requests or remove workspaces there.

So the Quickstart's desktop reader reads "Starting workspaces" and "Trying something several ways" as things they can do, and neither works for them. "Desktop harness" reads as one option among others, though desktop has no built-in models. The list leaves out opencode.

Proposed fix
  • Tag Starting workspaces, Pull requests and removing workspaces and Trying something several ways with the same inline "Web app only" marker used elsewhere.
  • Replace the buried sentence with a callout at the top of the Coordinator section: "On the desktop app the Coordinator can read, arrange and send work to existing workspaces. To start new ones, use + in the Workspaces menu. To open a PR or delete a workspace, use the workspace's … menu."
  • Quickstart "Keep going": point to the Workspaces menu for a second workspace (it already does), and link to the variants section only with the web-app note.
  • skills.mdx: note that screenplay-try-variants needs the web app.

Recommendation: Fix the docs now. Whether the desktop Coordinator should get plan and confirm cards is a separate product question. The refusal text the Coordinator relays is also wrong on desktop; see bugs.

Recommendation: Delete the sections now. Wiring the feature is a separate call for you, and the docs shouldn't promise it meanwhile.

  • Introduction: change the bullet to "Try it full screen. Open any workspace as a clickable prototype in play mode."

Recommendation: Fix the copy. If live URLs or synced knobs in the player are wanted, that's a product ticket.

06

The Quickstart has gaps that stop people before step one

High
quickstart.mdx
Today
  • "macOS. Download the latest Screenplay.dmg." The build is Apple Silicon only, and the file is Screenplay_<version>_aarch64.dmg (apps/desktop/scripts/release.mjs:207). Intel Mac users find out after downloading.
  • "A local folder or any git repository." The folder has to be a git checkout; a plain folder fails with "Not a git repository" (lib/sandbox/local/worktree.ts:279).
  • The sentence about New canvas is split by a stray blank line before <kbd>N</kbd> and renders as two paragraphs.
  • "Or pick Use a device code" only shows in builds with a GitHub client ID and when gh has no token.
  • The page mentions a Get started checklist but never names its three steps (Add a repository, Ask the Coordinator for a change, Open the Workspace), which match the Quickstart's own steps.
  • The step-5 screenshot reuses hero, which shows the workspace chat. The step describes the panel staying on the Coordinator with a task card.
  • There's no mention of updating: the desktop app has no auto-update, so users need to know to download new releases.
Proposed fix
  • "A Mac with Apple silicon (M1 or later)." Link to the Releases page and name the file pattern.
  • "A git repository: a local clone, or one on GitHub."
  • Remove the stray blank line.
  • Say the checklist's three steps match this page's steps.
  • Add a new docs screenshot of the Coordinator with a task card after the first ask.
  • End with one line: "Screenplay doesn't update itself yet. Download new versions from GitHub Releases."

Recommendation: Small edits with a high payoff. Ship them in one PR.
